你是一名擅长创意网页、游戏官网、Three.js 3D 场景和电影级运镜的前端工程师。请在当前项目中直接实现一个完整可运行的沉浸式游戏世界观网站，不要只输出设计建议、概念稿或静态页面。

网站名称为《九州：量天》。核心主题是“国风巨构与渺小人物”，通过真实 3D 场景、连续镜头运动和实验性排版，表现“天地为构，人如微尘”的尺度反差。

一、整体风格

- 采用“中国古典巨构 + 建筑蓝图 + 现代实验性网页”的视觉风格。
- 主色使用高饱和电光蓝 #2438FF，辅以暖白 #F2F0E9、近黑 #090909；朱红 #B64032 只用于人物披风、宫门、印章和关键选中状态。
- 3D 场景同时包含实体材质与白色线框：建筑边缘、斗拱、栏杆、山体和机关上覆盖细密蓝图网格、轮廓线、坐标刻度与工程标记。
- 建筑以白玉、石材和青铜为主，云雾使用半透明的蓝白色体积层次，整体明亮、宏大、干净，不要做成黑暗地牢。
- 中文标题使用宋体或明朝体，英文、编号、坐标和按钮使用极简无衬线字体。
- 使用超大标题与极小参数文字形成对比，排版具有建筑图纸和展览目录的感觉。
- 场景使用重檐、斗拱、盘龙柱、汉白玉栏杆、云纹、回纹、朱漆大门、青铜浑天仪、松柏、长袍等经典中式元素。
- 不要做成日式神社、西方奇幻城堡、赛博朋克城市或普通仙侠卡牌页面。
- 避免玻璃拟态、廉价霓虹、渐变紫背景和大量圆角卡片。

二、世界观内容

上古时期天柱倾断，天穹向人间沉降。旧神朝将宫殿、龙脉、山岳与机关城升入云海，建成四座维系天穹的巨构。

千年之后，凡人生活在巨构的阴影下，将其视为神迹，却不知道巨构维持天穹的代价，是不断抽取人间的山河气运。

玩家扮演“量天人”，能够测量天地尺度、解读上古建筑纹样。玩家需要穿越四座巨构，寻找散落的“天穹印”，最终决定修复旧秩序，还是让天地重归人间。

世界包含三个势力：
- 守阙廷：维护神朝遗迹，认为牺牲人间是延续天穹的必要代价。
- 量天司：记录巨构与山河变化，试图寻找两全之法。
- 归尘盟：主张摧毁巨构，让众生脱离神朝留下的秩序。

每个区域都要包含地点介绍、所属势力、当前危机、核心任务和一段完整中文叙事，不使用占位文案。

三、页面布局

1. 主场景
- 使用固定全屏 WebGL 画布作为页面主体，所有界面元素叠加在 3D 场景上。
- 不采用传统的“海报、特点卡片、角色列表、页脚”分段布局。
- 当前场景始终同时包含人物与巨构，不以纯文字页面打断探索。

2. 顶部导航
- 左侧为“九州 / JIUZHOU”标志与小型方形印章。
- 中央为四个编号选项：
  01. 天阙
  02. 龙廊
  03. 山海
  04. 璇玑
- 当前选项使用朱红色编号、下划线或实心标记，其余选项保持白色或黑色细线样式。
- 右侧设置“世界志”和“进入世界”按钮。

3. 场景信息
- 左下角放置当前区域的超大中文标题和较小的英文标题。
- 标题下方显示两句剧情文案、所属势力和当前任务。
- 右下角显示区域编号、虚构坐标、海拔或尺度参数，例如：
  SCALE 1:2400 / ALTITUDE 9,000 ZHANG / REALM 01。
- 页面右侧设置竖向进度条和“SCROLL TO EXPLORE”提示。

4. 世界志抽屉
- 点击“世界志”后，从右侧展开宽约 400px 的抽屉。
- 内容包含世界起源、四方区域、三大势力、玩家身份和编年史。
- 抽屉打开时保留部分 3D 场景可见，不要跳转到独立文档页面。
- 移动端改为底部抽屉，并保证文字可读和可关闭。

四、交互流程

1. 加载与序章
- 加载时显示细线进度条、百分比和“正在丈量天地”等简短文字。
- 加载完成后进入一段不超过 4 秒的序章运镜，用户可点击或滚动立即跳过。
- 序章结束后默认停在“01 天阙”，四个选项始终可点击。

2. 场景待机
- 云雾、人物衣摆、飞鸟和机关保持缓慢运动。
- 鼠标移动只产生轻微视差，不允许大幅拖动后破坏原有构图。
- 人物保持朝向巨构，营造“即将启程”的感觉。

3. 切换选项
- 点击顶部选项后，先更新编号和选中状态，再执行对应相机动画。
- 镜头沿预设路径平滑移动，场景文案在转场中段交叉淡入淡出。
- 不同区域之间可利用穿过云层、建筑遮挡或短暂黑场完成场景交接。
- 不允许简单切换背景图，也不允许没有运镜的硬切。
- 转场期间重复点击应被忽略或平滑重定向，避免相机状态混乱。

4. 滚动探索
- 每个区域包含 3—4 个滚动关键帧。
- 滚动时持续推进当前镜头，而不是把 3D 场景滚走。
- 向上滚动可以准确逆向播放。
- 滚动进度与右侧进度条同步。
- 到达区域末尾后，显示“前往下一境”，点击后切换至下一个选项。

5. 功能按钮
- “世界志”打开世界设定抽屉。
- “进入世界”展开当前区域的任务简报，不要跳转到不存在的游戏页面。
- 提供减少动态效果选项；没有真实音频时，不要设置无效的声音开关。

五、每个镜头要求

镜头 00：序章·丈量天地
- 开场为电光蓝空间中的白色建筑线框，镜头贴近一个人物线框剪影。
- 镜头缓慢后移，观众逐渐发现人物站在巨大斗拱的一小块结构上。
- 摄影机继续穿过斗拱和云层，实体建筑材质逐步显现。
- 最后拉远至云上宫殿全貌，超大标题“九州：量天”与副标题“天地为构，人如微尘”出现。
- 序章必须完成一次“人物近景 → 建筑局部 → 巨构全貌”的尺度反转。

镜头 01：天阙·云上神京
- 一名白衣旅人站在云海中的汉白玉平台上，位于画面下方。
- 远景是贯穿云层、顶部超出画面的多层宫殿与朱红天门，近景用松枝形成遮挡。
- 起始机位位于人物肩后，高度接近人眼，使用低角度仰视。
- 第一段滚动：镜头缓慢向后移动，人物缩小，宫殿基座和门柱逐渐显露。
- 第二段滚动：镜头向上升起并穿过薄云，揭示重檐、斗拱和更高层的建筑。
- 最终镜头：大幅拉远，人物不超过画面高度的 8%，但仍能通过白色衣袂辨认。
- 运镜重点是垂直尺度，不要让宫殿看起来像普通大小的庭院。

镜头 02：龙廊·万里丹陛
- 一条似乎没有尽头的巨型长廊，盘龙浮雕、柱础、栏杆和屋檐都远大于人物。
- 一名朱红披风的小人沿长廊行走，成为冷色场景中的视觉锚点。
- 起始镜头贴近人物侧面，以横向跟拍方式移动，前景巨柱不断遮挡画面，形成强烈视差。
- 第一段滚动：镜头逐渐降低并靠近地面，突出柱础和人物的高度差。
- 第二段滚动：镜头沿长廊中轴快速拉远，显露重复延伸的柱阵与屋顶。
- 最终镜头：从长廊另一端回望，人物成为远处的一点朱红，建筑向远处消失。
- 运镜重点是纵深与重复结构，不要只围绕人物旋转。

镜头 03：山海·悬空古岳
- 巨型山岳倒悬于云海，青铜锁链连接浮空祭坛，远处存在瀑布、古树、仙鹤和残碑。
- 小人站在向前突出的悬崖边缘，脚下云雾不可见底。
- 起始镜头隐藏在云雾中，只能看到锁链与瀑布局部。
- 第一段滚动：镜头穿过云雾，沿锁链向前推进，逐渐发现悬崖上的人物。
- 第二段滚动：镜头绕过人物并向上抬升，揭示人物背后的整片倒悬山岳。
- 最终镜头：继续大幅拉远，展示多座浮山与祭坛组成的庞大体系。
- 运镜重点是“局部看似山体，拉远后才发现只是巨构一角”的尺度反转。

镜头 04：璇玑·青铜机关城
- 巨型浑天仪、青铜齿轮、榫卯梁架和环形天轨构成缓慢运转的机关城。
- 小人站在狭窄悬桥或齿轮边缘，所有机关结构都比人物大数十倍以上。
- 起始镜头贴近缓慢旋转的青铜刻度和纹样，人物暂时不可见。
- 第一段滚动：镜头穿过浑天仪圆环，沿齿轮切线运动，逐渐显露悬桥上的人物。
- 第二段滚动：镜头围绕人物做半圆环绕，同时继续拉远，显示周围更多机关。
- 最终镜头：快速但平滑地拉至全景，揭示此前经过的圆环和齿轮只是机关城的一小部分。
- 机关运动必须缓慢、沉重、有惯性，不要像轻巧的钟表玩具。
- 运镜重点是机械结构的层层嵌套与最终规模揭示。

所有区域的最终定格镜头都必须同时包含人物与巨构，不能只展示建筑，也不能为了人物特写失去尺度对比。

六、技术要求

- 优先沿用当前项目技术栈，使用 Three.js；React 项目可使用 React Three Fiber 和 drei。
- 使用 GSAP 管理相机动画、场景切换和滚动关键帧。
- 必须使用真实可操控的 3D 场景，不得用视频、GIF或静态背景图模拟相机运动。
- 将区域内容配置化管理，每个配置包含：
  id、名称、剧情文案、势力、任务、场景资源、相机位置、观察目标、滚动关键帧和转场路径。
- 选项切换只更新统一状态，不要复制四套页面组件。
- 建筑可使用本地 GLB 模型、模块化几何体和实例化组合。
- 即使模型需要简化，也必须保留人物比例、空间层次、完整运镜和最终尺度揭示。
- 使用雾效、柔和阴影、环境光和前后景遮挡增强纵深。
- 控制设备像素比，复用几何体与材质，按需加载区域资源，并及时释放不再使用的资源。
- 桌面端保证流畅；移动端减少粒子、阴影和模型复杂度，但保留人物与巨构的对比。
- 支持键盘操作、清晰焦点状态和 prefers-reduced-motion。
- WebGL 不可用时，提供可读的完整世界观内容与简化场景回退。
- 完成后实际运行并检查构建、四个选项切换、正反向滚动、相机路径、世界志抽屉和移动端布局。
- 确保没有资源缺失、相机抖动、文字遮挡、重复点击错乱或控制台报错。
- 最终交付完整可运行代码及启动命令。
