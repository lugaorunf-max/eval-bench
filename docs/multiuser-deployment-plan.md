# 多人部署下一批方案

状态：设计方案，2026-10-31；本轮未连接或更改服务器，以下能力不能当作已上线。

## 数据和权限

- 云端 Next.js + PostgreSQL 管理用户、团队、案例版本、文章、资料关联和任务。公共案例在团队内共享；“公共库”不自动意味着互联网匿名公开。
- 用户通过邀请加入团队。文章、对话、未公开的测试和媒体默认仅所有者可见；未来分享文章须显式授予权限。成员不能通过猜 ID、文件地址、下载、导出、搜索、批量接口、会话或历史版本访问别人的私有内容。
- 数据增加 teamId、ownerId、visibility；文章资料关联按 articleId 和访问者权限校验。后台任务保存发起者、目标文章、执行设备和授权范围，恢复时不改归属。旧文章迁移给当前用户，无法确认归属的记录由管理员分配，不自动公开。
- 案例保存不可变版本和修改者；同事编辑使用版本冲突检查，不能覆盖已有测试快照。共享封面、提示词和必要输入附件上传云端。

## 文件分层

- 云端保存必要共享图片、案例封面及用户主动发布的媒体副本。使用存储适配接口，可先使用独立挂载目录，后切对象存储；下载先鉴权，短期链接不取代权限判断。
- 大视频、GIF 原件默认本机。云端只记文件哈希、设备编号、尺寸、类型、缩略图和可用状态，不上传本机绝对路径。设备离线显示不可用，不生成看似有效的公共链接。
- 用户选择“发布到团队”才上传共享副本，后台校验哈希、类型及大小。文章需跨设备阅读或导出时，先列出仍仅在本机的依赖，用户确认同步。删除云端副本不擅自删本机原件。

## 本机执行

- 各成员运行自己的本机服务，登录云端后做一次设备配对，获得可撤销的设备令牌。Agent 凭据和 Chrome 登录仍留本机，不通过网站提交模型账号密钥。
- 本机主动通过 HTTPS 领取本人授权的任务，限定设备、用户、文章和工具；云端不对用户电脑开放任意文件或命令接口。输出与用量按任务上传，需要共享的文件另行确认。
- 现有测试 runner 的设备领取机制可复用，但媒体工具、写作工具和 Chrome 配对目前还是本机通路，必须独立做用户和设备授权，不能认为已有 runner 就完成多人接入。
- Chrome 扩展需要明确允许最终网站域名并与本机服务配对；不能把现在仅接受 43110 的开发接口直接放开 CORS 后暴露公网。

## 部署隔离

在服务器新建独立应用目录、非 root 应用账号、端口、数据库账号及数据卷。先只读盘点已有服务和反向代理，再增加专用域名／路径及 HTTPS，不修改其他应用的路由和进程。上线前备份本机业务数据，在隔离库做迁移演练、回滚及文件校验。

## 验收顺序

1. 两个账号确认文章、对话、测试、关联和文件隔离，覆盖直接 URL、下载、导出及批量请求。
2. 两人可浏览公共案例，各自选用不会改动对方文章，案例并发编辑不覆盖历史。
3. 两台本机服务各自领取任务，停止、断线和恢复不串用户、不重复执行。
4. 本机视频离线可识别，主动共享后其他成员可预览与插入，媒体引用可追溯。
5. 云端备份、登录会话保护、账号撤销、设备撤销、恢复和服务器原有服务回归通过后才上线。
