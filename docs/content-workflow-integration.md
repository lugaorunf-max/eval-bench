# 三人内容工作流整合方案

本文包含历史讨论，当前入口与实现状态以文末“统一内容库 v3”及前端规范第 29 节为准。

历史状态：内容工作流 v1，2026-10-26。用户确认资讯与实战两条文章路径，共用选题池和 AI 写作，并增加按需素材处理。本轮仅更新 Figma 与文档；新增页面、接口及协作功能尚未在网站实现。

现有网站增加选题池和 AI 写作。信源聚合工具通过接口推送候选选题；文章结构工具提供可引用的结构模板。成员在选题池勾选可做的选题，再进入 AI 对话讨论切入角度、形成文章框架。案例评测继续使用现有三个页面，通过资料引用接回文章。内容归团队工作区，不绑定某个人的电脑或收件箱。

## 分工与数据归属

| 模块 | 主责 | 向工作台交付 |
| --- | --- | --- |
| 信源聚合 | 信源同事 | 新闻与来源、摘要、发布时间、发现时间、主题标签、候选案例线索 |
| 文章结构 | 结构同事 | 有来源和版本的结构模板、适用主题、章节组织、论证方式；若具备写作能力，可另外提供提纲或草稿生成服务 |
| 案例评测 | 你 | 案例标准化、模型测试、产物与耗时用量、人工评审、可引用结论 |
| 选题与成稿 | 三人中指定一人兼任内容负责人 | 人工确认选题、组织叙述、协调修改、终审与导出 |

信源原始记录和结构模板由对应工具维护权威版本；工作台保存接收版本和被稿件采用的快照。工作台是选题、稿件、案例、测试及其关联关系的权威来源。接口更新不能覆盖已经编辑的草稿或悄悄替换已采用的结构。

## 两个页面及主流程

1. 信源工具将标题、摘要、来源、发布时间、采集时间、关键词和候选案例线索推入选题池。不同报道可关联同一话题，原始来源仍保留。
2. 人工勾选本次使用的信源，跨搜索、筛选和分页保留；长期待做通过收藏保存。此约定替代此前勾选即持久入选的方案。不要求先创建项目、文件夹或填写完整立项单。
3. 选题池提供关键词搜索、全部／未引用／收藏视图、时间范围与排序。关键词查标题、摘要、关键词；默认按发布时间从新到旧。时间范围按发布时间筛选，另提供按采集时间排序。发布时间未知时明确标注，不当成新发布。结果数量与完整入选集合数量分别显示。
4. 点击「生成资讯」或「创建实战文章」，把本次选中的信源加入对应写作上下文。资讯首次确认模板和引用后生成；记住模板后可直接生成。实战先明确问题，再确认案例、Agent 与模型，才发起执行。用户可以移除无关项、围绕其中一条聊，也可以明确要求组合多个主题。入选与「已用于文章」分别记录。
5. AI 写作采用对话形式，支持追问读者、角度、事实依据，先形成框架，也允许后续扩展正文。结构模板在参考资料中挑选，不再增加一级素材库。结构拆解与写作生成是不同能力，需要分别确认同事的服务是否提供。
6. 框架默认以消息中的简版建议呈现；需要修改时才展开编辑面板。对话与框架版本分别保存，模型建议只有显式采用后才更新当前框架，不能覆盖人工修改。
7. 按框架需要推荐案例；人工确认案例提示词、输入和执行配置后，进入已有评测流程。结果按具体 Attempt 与产物版本引用回对话或稿件，人工确认采用后进入文章。
8. 成稿由负责人核对来源与实际测试结论后导出，暂不自动发布公众号。

第一版不使用一条强制的八阶段状态链。本次选择、收藏、对话进度、框架版本、测试状态与评审结论各自独立。AI 写作的会话列表可置顶与命名；默认只展示对话，历史列表可收起，框架与参考资料按需打开。

## 页面信息与筛选约定

| 选题池 | AI 写作 |
| --- | --- |
| 搜索、时间范围、时间排序同一行 | 顶部会话标题、参考资料、当前框架入口 |
| 全部／待筛选／已入选切换与当前匹配数 | 左侧可收起的历史对话 |
| 行内入选勾选、缩略封面、标题、摘要、主题、来源、发布时间 | 中央对话和底部输入框，模型信息清晰展示 |
| 底部本次已选数量与资讯／实战双入口 | 按需展开的框架编辑及版本保存 |

搜索与时间范围共同限定结果；状态视图进一步限定同一集合。清除筛选不取消本次选择；开始下一篇文章时不自动复用历史勾选。时间边界使用工作区时区，自定义范围包含起止自然日；相同时间用稳定 ID 作为次序依据。缺失发布时间的记录在默认排序中置后，开启发布时间范围时不匹配，并提示可切换到采集时间查看。未来网页需覆盖加载、空结果、接收失败和重复推送状态；Figma 当前画板为布局及代表状态，不等同于这些功能已经实现。

文章与案例为多对多关系。每个引用固定具体来源／模板／产物版本，重跑或重新采集不会改动旧稿。候选案例线索经人工整理后才能进入正式案例库，不自动成为可执行任务。

## 接口约定草案

以下路由为拟议接口，当前尚未实现。

| 接口 | 用途 |
| --- | --- |
| POST /api/integrations/v1/source-items | 接收新闻、信源与案例线索 |
| POST /api/integrations/v1/structure-templates | 接收结构模板的新版本 |
| GET /api/integrations/v1/jobs/{jobId} | 查询明确分配给当前工具的处理任务 |
| POST /api/integrations/v1/jobs/{jobId}/claim | 独立领取处理任务，重复领取需校验执行锁 |
| POST /api/integrations/v1/jobs/{jobId}/results | 回传提纲、草稿或推荐案例等处理结果 |

每条推送包含 producer、externalId、revision、schemaVersion、kind、payload；关联某个选题的处理结果还包含 editorialItemId 和 jobId。凭 producer + externalId + revision 去重，相同重试返回同一接收记录；同一版本编号出现不同内容时返回冲突，不能静默覆盖。长任务接收后返回任务编号，稍后更新状态，不让 HTTP 请求一直等待。

每个工具使用独立集成凭据，只能写入分配给自己的内容类型。接口有接收记录、处理状态和重试次数；发送方保留待发送队列，失败重试。第一版用普通 HTTP 与数据库任务记录即可，不先引入消息队列或独立微服务体系。

选题图片为拟新增字段：coverUrl 或受控附件文件 ID、来源、替代文本、裁切位置及可选的人工覆盖版本。优先接收原文封面；人工更换封面后，同一信源再次推送不覆盖人工版本。无图和加载失败使用相同占位，不阻止入选或进入写作。导入图片的校验、缓存和缩略图处理属于后续接口实现，本轮只完成设计。

附件单独上传，结构化记录引用文件 ID。信源字段至少包括标题、来源 URL、作者或发布方、发布时间、采集时间、摘要与主题；结构模板至少包括名称、适用范围、章节树、论证说明、参考来源与版本。第三方抓取的数据先校验再入库，不直接成为案例或可执行任务。

## 推荐与成稿的依据

第一版先按主题、任务类型、考察能力和产物格式匹配候选案例，再考虑语义检索。区分“匹配度”与“模型能力评分”，不把推荐算法的分数当作评测成绩。

稿件素材包由选定版本的提纲、信源、模板和评测证据组成。每条证据包含案例要求、模型和测试时间、实际产物、评审意见及局限。只有人工确认采用的结果才进入稿件；后续新的结果需要显式采用才会更新草稿。暂不做自动发布公众号。

## 共享服务器与本机执行

共享服务保存团队内容、状态与证据；各人的本地执行器负责需要本机安装与登录的 Agent。服务器无法直接读取同事电脑上的 Agent。

如果第一阶段尚未建设本地连接器，可以先共享内容收件与选题协作，评测仍由当前本地网站执行，手动关联导出结果；连通服务器下发任务、本地执行、回传进度后，再统一评测入口。公开接收推送前需要为网站补齐团队登录、权限及集成身份，不能简单把现有本机管理接口直接暴露出去。

## 实施顺序

第一阶段：确认本轮 Figma；与两位同事对齐各一条推送样例，确定字段、版本和身份。实现选题池接收、去重、搜索、时间筛选排序和持续入选，跑通资料带入写作。

第二阶段：接入实际可用的对话／写作能力与结构模板，保存会话和框架版本；补齐本地执行器到共享服务的连接、进度回传与证据引用，形成从选题到成稿的闭环。

第三阶段：在闭环稳定后增加语义推荐、批量生成和自动质量检查。人工确定选题、确认案例执行、采用测试结论和最终发布这几个决策点先保留。

## 资讯、实战与媒体处理（2026-10-26 已确认设计）

资讯可由单条信源生成解读，也可多选合成汇总。文章类型按类似 Skill 的方式组织规则，界面使用文章类型与模板名称；引用资料保持来源对应关系。资讯生成不自动发布，人工检查和修改草稿。

实战从文章关联已有或新建案例，明确勾选本机 Agent 并确认其模型。测试产物与录屏分别管理：第一版支持人工录屏上传，不假定执行器自动录像。实际测试记录和采用产物固定版本，回填文章时保留关联。

素材处理支持视频截取、切分、裁画面、多段拼接和压缩，以及视频转 GIF；GIF 支持截取、裁画面、拼接、尺寸／帧率／色数压缩和循环。原文件保留，估计体积与实际导出体积分开表达。导出可仅下载或作为素材副本加入文章。复杂字幕、自动录屏和自动发布不属于第一阶段。

Figma 全部整合到内容工作流 v1，v2 已删除，保留 v1 风格规范。设计稿只演示代表状态与跳转，不代表媒体编码、上传、LLM 生成、数据库引用或任务派发已实现。

## AI 写作简化（2026-10-26）

取消独立的模板与引用配置页，资讯与实战统一进入文章对话。一篇文章对应一个对话；文章类型和引用资料位于输入框，模板放进类型设置。资讯从选题池带入资料后直接生成，实战先讨论问题，再添加案例。AI 回复先展示文章／框架卡片，草稿只有显式打开时才展开右侧编辑区；关闭编辑区回到单列聊天。原先默认聊天与正文并列的画板已原位替换。视频处理和原有测试入口保留。以上仍是 Figma 方案，未修改应用代码。

## 实例与素材优先（2026-10-26 本轮确认）

文章引用具体实例或素材，不固定绑定某个案例，也不强制发起本机执行。案例是可选任务模板；实例是一次实际操作及其结果，可来自系统执行、外部 Agent 或人工教程。纯素材可直接上传，不要求先创建实例。

引用选择器提供已有实例、素材文件和导入新实例。导入至少记录名称、做了什么、实际结果；提示词、Agent、模型和案例关联可选，未记录信息不补造。文章可引用不同案例下的不同结果版本。

引用时分别决定给模型参考哪些任务／提示词、实际结果、操作步骤与备注，以及哪些附件加入候选素材。模型先基于文字资料组织文案；视频、GIF、截图由人确认插入段落。需要理解视频时再提供关键帧、转写或人工说明，不能仅因上传而假定模型已理解。

06 页框架全文直接显示。原文章专用测试配置替换为结果与素材入口，系统执行与人工导入统一检索；执行仍使用原发起测试。素材导出支持另存候选、替换已采用或仅下载。原文件、实例来源、引用版本及正文位置分别保留。以上均为设计，本轮未实现相关接口。

## 最新设计调整 · 2026-10-26 · 尚未同步网页

结果入口统一为「结果与素材」，纳入原运行结果的批次、模型产物、执行耗时、tokens、对话轮次、评审和下载。系统执行与人工导入在同一模块管理，分别保留数据来源和缺失指标。

写作以当前可编辑文档为主，对话生成大纲或初稿后可以直接修改。用户在光标处右键选择实例和素材，固定引用位置与结果版本；资料参考卡不自动成为发表正文，媒体需明确插入。新增引用可触发全文或当前章节的修订建议，先预览差异，再逐处采用。AI 使用当前手改稿件和新引用，不直接覆盖人工版本。

## 统一工作流 v2 · 2026-10-27 · 已同步网页

用户确认采用四个入口：热点检测与选题、案例测试、结果与素材、文章创作。保持现有侧栏设计，不重新建立项目、文件夹或文章类型配置页。

共同路径为抓取信息、聚合来源、人工确定选题。资讯直接添加一条或多条选题到文章参考资料，通过自然对话生成和修改草稿，再插入已挑选的图片、GIF 或视频并导出。实测类在确定问题后寻找案例线索，补齐完整提示词和输入，复用本机 Agent 配置执行；查看真实结果后整理媒体，再把证据与媒体分别加入文章。可以先写大纲再补测，也可以导入外部操作和教程结果，跳过本机执行。

选题台和原选题池共用一个入口，来源映射保持旧文章参考 ID 与快照。确认选题、收藏、用于文章分别表达不同状态；使用一条资料不会强制把所有相关报道送入文章。

外部案例线索与可执行测试案例保持区分。寻找案例恢复标题选词、规则提词、跨平台链接、按需 API、插件控制和多链接粘贴；外部页面内容及媒体需要实际采集、核对和归档，不将外部演示冒充本机效果。

测试批次和案例结果属于同一结果工作区的两种视图。原批次名称、置顶、Agent、模型、耗时、Token 与多轮记录保留；人工导入仍明确没有自动执行用量。演示素材支持独立上传，也可由结果整理得到。

文章创作仅含历史稿件、正文编辑与 AI 助手。资讯、提示词、输出与观察加入本篇上下文；媒体明确插入正文。重跑、重新采集不替换旧稿证据，AI 修订仍需人工采纳。当前未接入公众号自动发布、Obsidian 同步或同事的文章结构服务；这些仍按真实接口另行接入。

## 统一内容库 v3 · 2026-10-30 实施

本节覆盖前文旧入口与“搜集库”归属；技术与页面细节以 `docs/library-reorganization-20261030.md`、前端规范第 29 节为准。

选题决定要写什么；寻找入口带着选题关键词跳往平台，手动或 AI 收集后，素材进入独立素材库，提示词任务进入案例库备选区。两者共享原帖来源，可以同时关联同一帖子，不通过复制库之间的文件来切换用途。正式案例确认后发起测试，具体执行结果保留 Agent、模型、对话与用量；截图、录屏与加工 GIF 回到素材库。文章选择这些资料作为 AI 上下文，并在正文位置单独插入媒体。

原帖、备选案例、可测试案例、实际执行与媒体文件分别保存含义。反推提示词是可编辑的复现任务，不冒充原作者隐藏提示词；收集到的外部演示不等于本机实测。文章以快照保存引用，选用关系归具体文章，重跑与重新收集不会替换旧稿。素材集合只是分组，不拥有文件；从文章移除、全局回收站、永久清理是三种明确不同的操作。

旧业务记录不删除。可靠来源和衍生关系通过可重入整理补齐，未知媒体保留待整理，不凭文件名推断测试结论。选题选项暂不简化，AppSo 信源覆盖核对交由同事；插件重载、登录和真实 X／知识库写作联调依用户安排执行。
