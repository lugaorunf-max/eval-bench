# 文章上下文工作流 · 2026-10-30

本轮方案与实现：网页修改，未改 Figma；保留已有业务记录，不推送远端。

## 业务边界

确定要写后，以文章作为搜集和实测上下文合理；案例、文件保留全局身份，文章只是选用关系，可以跨文章复用。一个选题能支持多篇文章，一篇文章也能引用多条选题，未确定写作的选题不必提前建空文章。用户确认案例库默认本篇，并可从全部案例选用。

AI 分类和效果评估不同。根据提示词可以建议场景、产物和考察范围，不能据此证明模型效果。原帖没公开的提示词无法被还原为原文，只能生成带来源、依据和未知项的复现草稿，确认后入库。此轮保留确认步骤，不把分类完成等同于已实测。

## 实现

1. 共用文章选择：搜集、案例、配置、结果、素材统一使用一个会话内上下文；写作打开具体文章亦同步该上下文。案例库默认本篇，另可选用公共库。
2. 选题详情先选择文章、保存该条来源为参考，再进入简化搜集页。保留原选题管理、筛选、旧来源与引用快照。浏览器采集插件选择文章目标，接收网站当前文章作为默认值；文章列表不再混选题。
3. RunSpec 增加可选 articleId；验证目标存在，纳入请求幂等比较，冻结到运行快照。所选案例增加文章选用关系，结果继承目标。旧记录不猜测归属。多篇使用同一案例只追加关系，不复制案例。
4. 新建提示词先持久保存为无假来源链接的需解析记录；Agent 做元数据分类，不执行提示词。验证枚举和数量，保留原文及输入附件。失败保留需解析，确认后复用同一幂等入库事务。原帖下载与视觉反推沿用原链路。
5. 结果卡缩小预览和文案，去掉重复操作及标语；结果详情合并效果与素材，明确提供自动化整理。执行文件与记录保留用量、原始附件下载和现有逐轮对话组件。
6. 程序自动录制、上传到结果、视频/GIF 衍生版本均继承文章关系；素材库默认筛选当前文章，仍能切到全部。整理素材不自动改正文；正文插入仍由写作侧定位。

## 自动化边界

网页下滑和真实画布拖动由程序执行、录屏并编码。页面不支持旋转时不能伪造成功；复杂交互可明确选择演示助手，Agent 只负责有限步观察和操作，编码仍由程序完成。没有可运行网页的图片、文案等不会被硬转成“可环绕”产物，可上传录屏或处理现有视频/GIF。程序、模型和素材均保留实际来源。

## 人工参与项

新版插件需要在 Chrome 重载，再在已登录 X 的标签使用；真实 X 下载、原帖截图、视觉反推应在连接后验证。本轮不自动重新登录、不导出 Cookie、不请求新增权限。知识库可用性与同事服务器独立，不影响本次库管理和程序录制验收。
