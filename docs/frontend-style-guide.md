# 测写前端风格规范

版本 v1.28 · 2026-10-30。适用于当前案例库、发起测试、运行结果，以及选题池、AI 写作与后续素材处理。本文作为后续前端设计与实现的默认基线；用户明确提出的新要求优先。

## 1. 风格与依据

白色内容区、浅灰侧栏，黑色承担主要操作，一级工作区通过图标与文字变色表示当前位置，淡紫底用于次级模块，蓝紫色保留为链接、焦点和轻量选中的亮色；布局紧凑但保留阅读间距。搜索框略微浮起，筛选控件使用轻微内嵌质感。图标圆润、克制，分类图标以灰度填充层次区分结构。文字、真实内容和操作关系构成主要层级。

现有实现依据：apps/web/app/library.css、unified.css、facets.css、polish.css、agents.css、top-workspaces.css 和 compact-workspaces.css。CSS 最终覆盖值与已经确认的交互作为现有页面基线。Figma 文件 SAx28mSn48Uv4f55PZxFAt 现统一为「Eval Bench · 产品交互原型」一个页面（沿用原 v1 的 68:733 页面 ID）。既有评测与内容工作流已合并，保留原 v1 风格规范，不再新建版本页面。

## 3. 字体与层级

网页继续使用系统字体栈：-apple-system、BlinkMacSystemFont、PingFang SC、Microsoft YaHei、system-ui、sans-serif。Figma 继续使用原稿已有的 Noto Sans SC Regular / Bold，作为跨平台中文设计替代；不要求网页换字体。

| 层级 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| 页面标题 | 24 / 32px，粗体 | 案例库、工作台、选题标题 |
| 区域标题 | 16 / 24px，粗体 | 分组、设置、章节 |
| 内容标题 | 13–14 / 21–22px，粗体 | 案例标题、选题名称 |
| 界面正文 | 12–13 / 20–21px | 列表、按钮、字段 |
| 阅读正文 | 14–16 / 24–28px | 稿件和模型输出 |
| 辅助信息 | 11–12 / 18–20px | 时间、来源、版本与说明 |

工作台信息可以紧凑；稿件与产物阅读区应保留舒适行距，避免为了填满屏幕拉长文字行宽。主要操作不使用极小字号。

## 4. 布局与密度

- 桌面设计基准画板 1440 × 1000；固定画板用于评审，真实网页按内容滚动。
- 主侧栏展开 208px，收起 64px；保留图标，收起后背景透明。
- 测试或选题列表次级侧栏通常 250px，窄桌面可为 230px；案例筛选侧栏 308px，筛选按钮排三列。
- 次级侧栏收起后不保留图标栏或底色，宽度归零，只留下展开按钮。
- 页面主要内容内边距 24–40px；紧凑列表和新增工作台按 24–32px 组织。
- 常用间距 4、8、12、16、24、32px。相邻行用 8–12px，内容分组用 16–24px。
- 列表优先使用清晰对齐的列和细分隔线，不把每一行都包装成大卡片。普通文字列表行可为 64–72px；选题池带缩略图行使用约 100px，信源行 88–104px。
- 文案结果外层阅读区宽度约 960px；可视产物可扩到 1280px。稿件正文建议 680–800px，视容器留出合理边距。
- 仅在当前工作需要时显示次级侧栏或详情抽屉；不默认叠加第三条常驻信息栏。

## 5. 圆角、边框与层次

| 元素 | 规范 |
| --- | --- |
| 搜索、按钮、下拉、标签 | 999px 胶囊圆角；分类筛选标签保留紧凑 9px 圆角 |
| 图标按钮、导航项 | 10–12px 圆角 |
| 卡片、结果阅读面板 | 16px 圆角 |
| 大浮动详情 | 20px 圆角 |
| 搜索框高度 | 40–48px；弹层或特定主搜索可为 56px |
| 普通操作高度 | 34–40px；紧凑操作 30–34px |
| 图标按钮 | 32 × 32px，显示图形通常为 18–20px |
| 分类标签 | 28px 高，6px 左右内边距，三列间隔 4px |
| 搜索阴影 | 0 3px 8px -2px rgb(36 41 51 / 6.5%) |
| 筛选内阴影 | inset 0 1px 2px rgb(36 41 51 / 5%) |

搜索焦点由外层容器统一描边，内部 input 不出现第二层框。选中筛选用浅蓝背景、强调文字或勾选；收藏选中必须显示实心星形。

## 6. 图标

- 优先复用 apps/web/public/icons/taxonomy/ 中已有图形，以及 lucide-react 中当前使用的圆头、圆连接 SVG。
- 分类图标使用两至三个灰度层次；选中态使用强调色，保留必要反白细节。
- 发起测试、侧栏展开与收起使用现有圆润版本，不重新画尖锐三角形。
- OpenAI 使用官网黑白 Blossom；其他 Agent 沿用已接入的品牌图标和原始比例。
- 图标按钮提供清晰的 title / aria-label；不能只用难懂图案表达关键操作。

## 7. 交互规范

- 主导航和次级导航的展开/收起按钮锚定各自侧栏容器，共用滚动坐标；移动抽屉整组定位。
- 保留一个展开/收起入口。按钮不位于被隐藏的内容中，收起不丢失筛选和键盘焦点。
- 案例详情、信源详情、结构预览使用浮动详情；执行日志或文件使用按需抽屉。
- 同一筛选组内多选表示匹配任一项，不同分组同时满足。已选项保持可见或有明确数量与查看入口。
- Agent 由人明确勾选；型号独立展示，以本地返回的可读名称呈现，提交保留原始 ID。
- 模型结果保持单个 Agent 的阅读视图，多个 Agent 用标签切换。
- 复制、评审和产物记录保留清晰层级，低频操作进入面板或更多菜单。
- 缺失指标显示未提供或已知部分，不用 0 冒充未知。

## 8. 选题池与 AI 写作的统一约定

本节为新增页面的设计约定，还不代表网页功能已经实现。

- 内容入口为「选题池」「AI 写作」，保留案例库、发起测试、运行结果；「素材处理」作为按需工具入口。结构模板归入写作参考资料，不另设一级素材库或强制阶段工作台。
- 选题池使用紧凑列表，显示本次勾选、缩略图、标题、摘要、主题、来源和发布时间。自本轮确认方案起，勾选改为「本次文章的引用选择」，跨搜索和分页保留；收藏独立持久保存，历史选择不自动混入新稿。
- 选题封面位于勾选框与文字之间，112 × 70px，12px 圆角、居中裁切；行高约 100px。无图或加载失败保持相同尺寸的中性占位，不能改变勾选框、文字或时间的位置。图片不承载唯一的标题或状态信息。
- 封面优先取来源文章的封面图，允许后续手动上传或更换；缺图不自动生成与事实不符的新闻图片。设计稿中的照片仅为示例，区别于实际原文封面。
- 搜索覆盖标题、摘要与关键词。关键词、时间范围、排序放在同一紧凑工具行；状态通过「全部／未引用／收藏」切换。时间范围默认全部，排序默认发布时间最新优先。
- 时间范围提供今天、最近 7 天、最近 30 天、自定义；排序提供最新发布、最早发布、最新采集。发布时间与采集时间分开存储，缺失的发布时间显示未知，不冒充采集时间。
- 状态、关键词与时间范围同时满足；结果数量指当前匹配数，底部已选数量指本次选择集合，不能互相混用。空结果保留清除筛选入口。
- 底部选择条提供「生成资讯」「创建实战文章」。资讯直接带着引用进入对话生成；模板在输入框的文章类型设置内确认或更换，不再经过独立配置向导。选题详情浮动卡片提供相同双入口；文章主要引用具体实例与素材，不强制绑定固定案例或先发起测试。
- AI 写作默认只有对话主视图，一篇文章对应一个对话；历史对话为可收起的次级侧栏。文章类型与引用入口放在底部输入框，模板收进文章类型设置，不在顶部常驻。正文阅读宽度约 800px，输入框固定在内容区底部；长会话只滚动消息区。
- 引用入口统一支持信源、已有实例、人工导入结果与独立素材。实例可来自系统执行或人工操作，案例关联、Agent 与模型均可缺省。框架在对话里直接完整显示，不折叠、不再单独展开编辑页；成稿正文仍可按需打开约 500px 编辑区。
- 明确区分给 AI 的写作参考和文章中的媒体。引用实例时选择任务／提示词、实际结果、操作说明与备注；附件进入候选素材后，由人选择段落位置再插入，不自动塞进正文。
- 结果侧拟统一为结果与素材，支持导入与检索；文章不复制一套测试配置。需要新结果时才进入现有发起测试。人工导入不伪装成执行成功，缺失指标显示未记录／未提供。
- 素材处理沿用胶囊控件和轻表面。明确区分截取时段与裁剪画面；时间线支持分段与排序，视频和 GIF 分别显示适用参数。导出显示估计体积，保留原文件，提供另存到候选素材、明确替换已采用素材或仅下载，保留与实例及原文件的来源关系。
- 本次选择、收藏、对话、框架采用、测试完成、产物评审分别保存状态。来源、结构和测试证据采用具体版本；示例明确标注，不冒充真实数据。

## 9. 后续工作约定

前端设计、Figma 页面及网页实现开始前先读本文。优先复用现有变量、组件和图标；新增规范先补入文档，明确当前已有规范与拟新增规范的边界。用户确认 Figma 后再按当轮授权同步网页。

验收时检查：三个核心页面及新增页面的圆角、图标和字号一致；主要信息对齐；展开/收起与窄屏不遮挡操作；长标题和状态数量变化不会突然挤动整个内容区；焦点和选中态明确。视觉验收与组件检查分别记录，不以其中一种替代另一种。


## 10. 本轮网页落地范围 · 2026-10-26

已实现 `/topics`、`/write`、`/write/:id` 与 `/instances`，沿用现有视觉规范。文章类型只在输入框底部选择「资讯汇总／案例实测」。开始对话页不再出现「按模板生成资讯」「先讨论一个角度」快捷按钮。资讯完整草稿和实测完整框架直接作为助手消息展示，不需要打开文章卡片才能阅读。消息区独立滚动，输入框保持可见。

引用保存选中信源或实例内容的快照；每轮回复同时保存当时的引用与文章类型。人工导入不创建测试执行、不补造指标。上传的图片或视频进入候选素材，不代表模型已理解其内容。写作复用真实 Agent／API 适配器，历史、命名、置顶、消息、耗时与返回的 tokens 本地持久保存，缺失用量仍显示未提供。未发送文字和所选模型在当前浏览器会话中保留。

本节为首次落地记录；最新实现范围见第 13 节。同事信源、知识库接口和视频／GIF 编码仍未实现。

## 12. 统一结果与文档编辑 · 本轮 Figma 设计 v1.8

本节记录已确认的 Figma 设计，覆盖前面与其冲突的旧设计。已同步的网页功能和边界见第 13 节。

## 13. 统一结果与可编辑文档 · 网页实现 v1.9

本节描述当前本地网页，取代第 8、10 节中以聊天消息为唯一稿件的旧实现。Figma 七个分区保持不变。

- 主导航只有「结果与素材」，`/instances` 显示全部实例，模块内切换素材文件。旧 `/runs`、`/r/:id`、`/a/:id`、`/materials` 地址继续可用并归入同一导航。置顶、命名、批次详情、Agent 切换、逐轮会话和原有产物评审保留。
- 实例采用紧凑表格，按 20 条分页，支持搜索、状态和时间排序。人工导入、待执行、失败、成功都纳入列表；用量累计已归档的会话轮次与重试，缺失部分标明「部分上报」。未知显示「未提供」，人工实例显示「未记录」，不填零。素材视图暂展示最近 300 个已存文件。
- 写作采用 Tiptap 文档编辑器，左侧可编辑稿件，右侧 360px 助手可收起，文章历史按需展开。正文区域随窗口自适应；窄屏助手为侧浮层，内部保留关闭按钮。圆角工具栏、白纸、胶囊按钮和灰色工作区沿用已有视觉语言。
- 正文支持标题、加粗、斜体、列表、链接、撤销、自动保存、Markdown 导出和最近 30 个版本检查点。每篇文章保存唯一当前文档，旧对话仍保留，旧文章首次读取会以最近完整助手回复作为可编辑初始内容。
- 右键菜单保留光标／选区锚点。引用完成实例、信源或素材时保存版本快照；实例可选择任务、结果、备注和可选指标。参考卡不作为正文导出。媒体明确插入光标位置并填写说明，非图片／视频文件作为附件链接。
- 助手可讨论、生成大纲／初稿或修订正文，范围为全文或选中的段落。首次生成只在未被修改的空文档中直接落稿；其余改动进入分块差异预览，可逐处采纳或全部放弃。AI 读取当前已保存的人工作品；引用和已插入媒体在修订中保留。
