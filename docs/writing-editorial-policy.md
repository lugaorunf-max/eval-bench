# 写作编辑原则 · 2026-10-29

用户确认在现有写作链路中加入科技媒体编辑原则，以信息取舍和证据约束改善文章质量。共用实现位于 `packages/core/writing-editorial-policy.ts`，由 `EditorialService` 加入各写作 Agent 的上下文，不改变界面或历史稿件。

## 接入顺序

本篇任务、当前正文和选区 → 已读知识库文章及服务返回的表达建议 → 本站编辑原则 → 引用交付协议。本站编辑原则对通用风格建议具有明确优先级；用户的具体任务、事实纪律、JSON 交付、真实引用校验、选区和并发修改保护继续生效。只使用原有一次生成，不新增二次润色调用。

## 实际规则

- 选材以阅读价值为准，不把可有可无一律删除。有趣、有辨识度且有依据的细节可保留，不要求每个细节直接证明主线或附带分析结论。
- 数字可以说明变化、支持判断，也可以因反差而有趣。删除没有阅读价值的参数和重复成绩，不设硬性数字上限。
- 案例细节需要实际读取的材料支持；搜索摘要不能替代原文，原作者陈述不等于独立验证。
- 依赖观看的效果判断应有对应媒体、测试记录或人工观察。只有文字时限定归属和范围；图片下载成功和附件文件名不证明效果。
- 证据不足的可选案例删去，主线必需或用户指定的材料保留具体缺口。不为叙事补全操作过程、画面和反应。
- 可选传闻不能靠加“未经验证”的免责声明留在正文，无关参数也不以批评参数堆砌为由重新列出。材料少就写短，不凑字数；缺少独立测试不自动成为负面判断。
- 参考文章的写法与本篇事实分开，历史助手回复和当前稿件不作为独立证据。
- 不强迫鲜明态度、反转、幽默和行业升华，不用推荐口头禅制造真人感；教程、讨论、大纲等仍服从实际请求。
- 正文不在每个趣味细节后附自我审稿说明，一般核查情况留在助手；影响读者判断的必要限制仍需写清。
- 正文和大纲进入编辑区，简短说明与知识库引用留在助手。

## 验证边界

上述内容是所有写作执行器共用的生成指令，并非新增的逐条事实验证系统。原有后端继续校验知识库文章 ID 与短引文、媒体地址和实际文件、文稿修订等。尚未新增网页断言与证据逐条绑定、视频自动观看或所有案例结论的自动核验；不能把提示词约束宣称为这些功能已完成。
